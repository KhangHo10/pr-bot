# PR Bot

An AI-powered pull request reviewer built with GitHub Actions and the Gemini API. This project automatically reviews pull requests by fetching the diff, sending it to an LLM for analysis, and posting a review summary as a PR comment. It is designed to work with no backend, no dedicated server, and no external hosting.

## Why this project exists

Pull request reviews are valuable, but they often take time. This bot helps automate the first pass of review by checking for:

- logic bugs or risky changes
- missing edge cases
- unclear or hard-to-maintain code
- general improvement suggestions

It is a lightweight way to bring AI-assisted code review into a GitHub workflow without complex infrastructure.

## How it works

1. A pull request is opened, synchronized, or reopened.
2. GitHub Actions triggers the workflow.
3. The workflow installs dependencies and runs the Python script.
4. The script fetches the PR diff from the GitHub API.
5. The diff is sent to Gemini for review.
6. The bot formats the result and posts it as a PR comment.

## Features

- serverless GitHub Actions workflow
- automatic PR review on update events
- structured output with summary, issues, suggestions, and merge verdict
- customizable review prompt and model configuration
- easy to adapt to other repositories

## Prerequisites

Before using this project, make sure you have:

- a GitHub account and repository where you can enable GitHub Actions
- a Google AI Studio account
- a Gemini API key
- Python 3.11+ for local testing

## Setup

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd pr-bot
```

### 2. Install Python dependencies

```bash
pip install -r requirements.txt
```

The required packages are listed in the project requirements:

```text
requests>=2.31.0
google-genai>=2.3.0
pydantic>=2.0.0
```

### 3. Configure the GitHub workflow

This repo already includes a workflow file at [.github/workflows/pr-review.yml](.github/workflows/pr-review.yml). The workflow does the following:

- runs on pull request events
- checks out the repo
- installs dependencies
- executes the review script

The workflow is triggered by:

```yaml
on:
  pull_request:
    types: [opened, synchronize, reopened]
```

### 4. Add the required GitHub secret

Create a repository secret named `GEMINI_API_KEY` in GitHub:

- Go to your repo
- Open Settings
- Go to Secrets and variables -> Actions
- Add a new repository secret called `GEMINI_API_KEY`

The workflow also uses `GITHUB_TOKEN`, which GitHub provides automatically for Actions. In most cases, no manual setup is needed for that token.

## Local execution

You can run the review script locally to test the bot against a PR or a simulated diff.

### Example environment variables

```bash
export REPO="owner/repo-name"
export PR_NUMBER="12"
export GITHUB_TOKEN="your_github_token"
export GEMINI_API_KEY="your_gemini_api_key"
```

Then:

```bash
python scripts/review.py
```

## How the script works

The main logic lives in [scripts/review.py](scripts/review.py):

- `get_pr_diff()` fetches the PR diff from GitHub
- `review_diff()` sends the diff to Gemini
- `format_review()` turns the model output into a readable GitHub comment
- `post_comment()` publishes the review to the PR

The bot expects a JSON-like review structure with:

- summary
- issues
- suggestions
- approve

This gives a predictable format for the AI-generated output.

## Customizing the bot for another project

You can reuse this workflow in almost any GitHub repository.

### Minimal adaptation steps

1. Copy the `.github/workflows/pr-review.yml` file into the target repo.
2. Keep the same workflow trigger if you want reviews on every PR update.
3. Add the `GEMINI_API_KEY` repository secret.
4. Ensure the repo has Python dependencies installed in CI.
5. Keep the script in a path like `scripts/review.py` or update the workflow command accordingly.

### Recommended customizations

- change the review prompt in `build_prompt()` to match your project style
- adjust the model name if you want a different Gemini model
- add PR labels or summary formatting for your team conventions
- filter the generated issues based on your stack or code quality rules
- change the severity levels or approve logic if your team uses stricter standards

## Important notes

- This bot is a review assistant, not a replacement for human judgment.
- It works best when combined with code standards, linting, and review policies.
- Make sure the repository permissions allow PR comments.
- Use least-privilege permissions where possible.

## Security considerations

- never commit your API keys to the repository
- prefer GitHub Secrets for environment values
- ensure the GitHub token has the minimum required permissions
- review generated comments before treating them as strict policy decisions

## Troubleshooting

### The workflow does not run

Check that:

- GitHub Actions is enabled for the repo
- the workflow file is in the correct path
- the repo has pull request events allowed

### The script fails with an API error

Check that:

- `GEMINI_API_KEY` is correctly added as a secret
- the API key is valid and has access
- the model name is supported by your Gemini setup

### The bot cannot fetch the PR diff

Check that:

- the `REPO` env value is correct
- the GitHub token has permission to read pull request metadata
- the PR number is being passed correctly from the workflow
